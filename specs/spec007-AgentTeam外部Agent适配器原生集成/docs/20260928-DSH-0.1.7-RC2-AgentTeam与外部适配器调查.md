# DSH 0.1.7-RC2 Agent Team 与外部适配器调查

调查日期：2026-09-28

## 1. 调查目标

确认 DSH `0.1.7-rc.2` 的实验性 Agent Team 能否在不修改 DSH Host 的前提下，把本插件已有外部 CLI Agent 作为原生 Team 成员管理，并明确官方 Web Team 面板和插件详情面板各自能展示什么。

## 3. Agent Team 的真实模型

### 3.1 成员和生命周期

- 一个顶层 DSH Session 隐式对应一个 Team。
- Lead 是真实 DSH `Agent`。
- teammate 是 Lead 的 continuable child，不能只用一次性调用结果代替。
- 后续 Agent 创建、Session、inbox、steer、interrupt 和 dispose 由 DSH continuation manager 管理。
- Team 状态写入 Lead Session，包括 `team/member`、`team/task`、`team/message/queued`、`team/message/delivered`。

这意味着一个“外部 CLI 进程”本身不是 Team 成员。若没有真实 DSH Agent/Session/continuation，它就没有合法的成员身份、mailbox 和销毁路径。

### 3.2 官方 Team 工具

观察到九个 Team 工具：

1. `spawn_teammate`
2. `send_message`
3. `list_agents`
4. `wait_agent`
5. `interrupt_agent`
6. `team_task_create`
7. `team_task_list`
8. `team_task_get`
9. `team_task_update`

插件不能覆盖这些名字，也不能通过写入内部状态让外部 CLI 冒充这些工具的调用者。

### 3.3 Web UI 的可见范围

Web UI 读取 Lead Session 的 `agentTeam` projection。官方 Team 面板可以展示：

- Team 标识和模式。
- 成员 roster、成员状态和会话入口。
- 共享任务、Owner、状态、依赖和 write scope。

官方 Team UI 不负责：

- spawn、interrupt 或删除成员。
- 展示完整 mailbox 时间线。
- 展示外部 CLI 的每一条工具调用、权限请求、问题、usage 和 provider session 详情。

因此“原生 Team 面板能看到 Proxy 成员”与“能看到外部 Agent 全部操作详情”是两个问题，后者必须由插件详情面板补足。

## 4. Profile 和资源限制

Agent Team Profile 会禁用传统 subagent 工具，并插入 Team service、Team tools 和 Team UI。观察到的限制包括：

- `maxMembers: 8`
- `maxTasks: 256`
- `maxPendingMessagesPerMember: 64`
- `maxMessageBytes: 65536`
- `disposalTimeoutMs: 5000`

Team 是单进程、共享 cwd 的模型，不提供 worktree 隔离、文件锁、跨进程 exactly-once 或自动释放任务 Owner。外部 Agent 适配器不能假装这些能力存在。

## 5. Provider 可行性

### 5.1 `SubagentProvider`

DSH `SubagentProvider` 的 continuable 接口主要是 `prepareContinuable()`，其职责偏向返回 seed；后续 Agent、Session、inbox、steer、interrupt 和 dispose 仍由 DSH continuation manager 管理。

插件可以探索自定义 provider，但必须先验证公开契约是否允许创建可持续 Proxy。若只能返回 seed，不能把外部 CLI 直接宣布为完整 Team 成员。

### 5.2 ACP provider

`@deepseek-ai/dsh-subagent-acp@0.1.7-rc.2` 是 one-shot ACP provider，不具备本 Spec 所需的 continuable Team 成员生命周期。因此 ACP 可以支持一次性外部调用实验，但不能作为第一阶段原生 Team 集成的依据。

## 6. 插件现有外部 Agent 能力

### 6.1 统一驱动契约

`src/host/cli-adapters/driver.ts` 已提供：

- `detect`
- `listModels`
- `executeTurn`
- `respondPermission`
- `respondQuestion`
- `steer`
- `followUp`
- `interrupt`
- `dispose`

已覆盖 Command Code、Claude Code、Kimi CLI、Gemini CLI、Pi Agent、Codex、OpenCode 和 Grok Build。

### 6.2 当前接入方式

`src/host/cli-adapters/feature.ts` 通过 DSH `llm/stream` 事件拦截外部 Agent 请求，读取插件 CLI session 配置，调用 `CodingNsCliAdapterRegistry.execute()`，并使用 `CodingNsDshMessageProjector` 投影回 DSH 对话。

`src/host/cli-adapters/registry.ts` 管理执行、恢复、分段、工具事件、权限、提问、中断和会话索引。

`src/host/native-session-bridge.ts` 将外部已执行工具写成只读 DSH 历史，不再次触发 DSH 工具执行器。

这些能力适合做 Proxy 的执行后端，但没有提供 DSH Agent 身份、原生 inbox 或 Team continuation。

## 7. 可行性结论

| 方案 | 结果 | 原因 |
| --- | --- | --- |
| 外部 CLI 直接成为官方 Team Agent | 不推荐，约 `2/10` | 缺少 Agent、Session、lineage、inbox、continuation 和原生 Team 工具上下文 |
| 伪造 Agent 或改写 TeamService 私有状态 | 禁止 | 破坏授权、projection、持久化和销毁语义，升级即失效 |
| ACP one-shot provider | 仅适合实验 | 没有可持续 Team 成员生命周期 |
| 原生 Proxy Teammate + 外部执行后端 | 推荐，约 `8/10` | DSH 管理成员和任务，插件管理外部进程和细节 |

## 8. 对本 Spec 的约束

1. 官方 Team roster/任务必须由真实 DSH Proxy Teammate 产生。
2. 外部绑定和事件必须由插件 Host-only store 管理。
3. 外部详情必须通过插件面板提供，不能要求官方 Team UI 展示其全部内部事件。
4. `ctx.inject(['agentTeams', 'subagents', 'events', 'sessionPersistence'])` 只是规划中的候选注入集合，真实字段和公开接口必须由 capability route 验证。
5. 没有公开 continuable Proxy 创建契约时，必须阻止直接实现任务，转入降级范围评审，不得读取私有状态。
